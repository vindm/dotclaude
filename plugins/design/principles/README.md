# `principles/` — teaching material for the design plugin

These docs teach the `/dotclaude:design` elicitation HOW to author each agent, skill, and rule it ships — read selectively in its Phase 3, based on what the project's UI actually has. Same role core's `principles/` played for `bootstrap` pre-v3: rationale and derivation logic, not a consumed artifact itself.

- `a11y-audit.md` — how to author an accessibility-audit agent (labels, hit targets, contrast, text scaling, reduced-motion).
- `audit-routing.md` — how to author the rule that orders which audit agent runs when several coexist.
- `design-benchmarking.md` — how to author the "name your benchmarks" rule that becomes the project's design-north-star.
- `design-system-reference-skill.md` — how to author the design-system entry-point skill every UI agent loads.
- `design-token-audit.md` — how to author the token-discipline sweep agent.
- `element-reuse.md` — how to author the Gate A reuse-verdict skill (borrowed copy/component on the wrong surface).
- `flow-audit.md` — how to author the whole-arc audit agent, both its live-walk and pre-captured continuity-grading modes.
- `interaction-audit.md` — how to author the chrome-promises-vs-handler-does integrity agent.
- `iterative-polish-autoloop.md` — how to author the continuous polish loop (reviewer + composition scan + backend-truth probe).
- `journey-mapping.md` — how to author the prior-surface inventory skill every other design agent depends on.
- `pages-audit.md` — how to author the cross-section consistency agent.
- `persona-testing.md` — how to author the outside-eyes copy lens (day-30 / partner / stranger tests).
- `product-designer.md` — how to author the senior-IC IA/flow/multi-screen designer agent.
- `quality-rubric.md` — how to design the project's operational S/A/B/C/D/F rubric.
- `ux-audit.md` — how to author the single-screen visual-polish agent.
- `visual-verification.md` — how to design the see-what-you-built discipline for visible output.
